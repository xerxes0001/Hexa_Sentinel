Problem Statement

A very real threat, with a very real gap

India is the second-most targeted nation globally for cybersecurity attacks. Yet the tools that could protect organisations are either too expensive, too cloud-dependent, or too silent when the internet goes down — which is precisely when attacks hit hardest.

🇮🇳
1.39 million cybersecurity incidents in India in 2024 — reported by CERT-In. BGP hijacking attacks on Reliance Jio, BSNL, and regional ISPs demonstrated that network-layer threats are immediate and real, not theoretical.

Three failure modes of cloud-dependent security tools

🔒

Privacy Risk

Every byte of network traffic metadata — source IPs, connection behaviour, packet statistics — must leave your premises and travel to a vendor's cloud for analysis. For financial institutions, government-adjacent bodies, and research organisations, this is a sovereignty concern and a DPDP Act compliance problem.

⏱️

Latency Blind Spot

Network attacks operate in milliseconds. A pipeline that routes traffic data to a remote cloud for AI inference introduces 80–300 ms of round-trip latency. During that window, an attack can propagate across an entire subnet. Sub-millisecond detection isn't a nice-to-have — it's the difference between containment and compromise.

📡

Offline Vulnerability

Sophisticated network attacks often deliberately degrade or sever internet connectivity — BGP hijacking is a prime example. A cloud-dependent security tool goes completely blind at the exact moment it's needed most. An on-device solution keeps protecting the network regardless of connectivity.

💡
The gap HexaSentinel fills: There is currently no widely available, open, on-device tool that combines real-time network traffic monitoring, ML-based anomaly detection, and natural-language threat explanation — all running locally on consumer-grade hardware. Placing the AI analyst inside the device — on the Hexagon NPU — eliminates the privacy risk, the latency gap, and the offline vulnerability simultaneously.
Background

Where HexaSentinel came from

HexaSentinel is built on SHYEN — a real-world BGP threat intelligence dashboard developed by the author. Understanding SHYEN clarifies what HexaSentinel is evolving, and why the transformation matters.

SHYEN (Security Hub for Yielding Edge Networks) features four autonomous agents:

BGPWatchAgent

Connects to RIPE RIS live WebSocket feeds and monitors BGP route announcements in real time, flagging anomalies such as unexpected prefix origins or sudden route withdrawals.

DNSHuntAgent

Monitors DNS resolution for high-value Indian domains, detecting DNS hijacking, spoofed responses, and cache poisoning attempts before they affect end users.

CertSentinel

Tracks TLS certificate transparency logs for Indian domains, alerting on newly issued or suspicious certificates that may indicate a man-in-the-middle setup.

AI Orchestrator

Correlates signals from all three agents and generates incident analysis reports. Previously powered entirely by the Groq cloud API — the foundational flaw HexaSentinel corrects.

Solution Overview

How HexaSentinel works

HexaSentinel runs silently on a Snapdragon-powered HP AI PC, watching all inbound and outbound traffic through a two-stage AI pipeline — both stages executing entirely on the Hexagon NPU.

1

Traffic Classification

An ONNX model classifies each 30-second traffic window as NORMAL, SUSPICIOUS, or THREAT. It processes 80 engineered features — packet rates, inter-arrival times, byte distributions, port entropy, protocol ratios — in under 5 ms on the Hexagon NPU.

2

Threat Analysis

When the classifier returns SUSPICIOUS or THREAT, the context is passed to Llama 3.2 3B on the Hexagon NPU. It generates a plain-English explanation of what was detected, why it's suspicious, and exactly what the user should do — no internet required.

Technical Architecture

The full picture — inside the device

Every component runs on the HP AI PC. Packets come in from the network interface and travel through two AI models on the Hexagon NPU before surfacing as human-readable alerts on the dashboard.

Component breakdown

Packet Capture Layer

Uses scapy (or pyshark) to capture all traffic on the active network interface. Packets are collected into 30-second windows from which 80 statistical features are computed — flow statistics, protocol distributions, inter-arrival time stats, SYN/SYN-ACK ratios, and payload indicators.

ONNX Anomaly Classifier

A gradient-boosted tree ensemble converted to ONNX format, trained on CICIDS-2018 (F1 > 0.97). ONNX Runtime runs it with the QNN Execution Provider, routing inference to the Hexagon NPU for sub-5ms classification latency per window.

Llama 3.2 3B (Qualcomm AI Hub)

The 4-bit quantized Llama 3.2 3B Instruct model compiled for QNN Runtime achieves 3–4× throughput over FP16 on Snapdragon hardware. It generates a <200-word threat report with severity, attack vector, and three immediate action recommendations.

React Dashboard

Adapted from SHYEN's codebase. Connects via local FastAPI WebSocket. Shows a live threat feed, D3 network graph, severity meter, Llama-powered AI explanation panel, and one-click CERT-In format PDF export.

Four technical advantages over the Groq cloud API

Inference Latency

Groq API averages 800–1200 ms round-trip for a 200-token completion. Llama 3.2 3B on the Hexagon NPU generates the same 200-token threat report in 8–13 seconds — and unlike cloud, this holds even when there's no internet connection.

Zero Data Egress

Network traffic metadata, source/destination IPs, packet statistics, and behavioral anomalies never leave the device. This satisfies DPDP Act (Digital Personal Data Protection Act, India 2023) compliance for organisations handling personal data.

Power Efficiency

The Hexagon NPU delivers the highest TOPS-per-watt ratio on the Snapdragon X Elite. Running Llama 3.2 3B on the NPU consumes roughly 3–5 W versus 15–20 W on the CPU — extending battery life on laptop deployments.

Air-Gap Compatibility

HexaSentinel operates identically on isolated industrial networks, secure government LAN environments, and locations with poor connectivity. Once the model is downloaded at setup, no internet is ever needed again.

🔧
NPU scheduling: Both workloads coexist on the Hexagon NPU without contention. The ONNX classifier runs in a continuous low-priority thread (30s windows, ~5ms each). Llama runs in a high-priority on-demand thread triggered only by SUSPICIOUS or THREAT events — a scheduling approach enabled by the QNN Runtime's priority queue mechanism.

How the ONNX model runs on the Hexagon NPU

# ONNX Runtime with Qualcomm QNN Execution Provider import onnxruntime as ort providers = [ ("QNNExecutionProvider", { "backend_path": "QnnHtp.dll", # Hexagon NPU backend "htp_performance_mode": "burst", "htp_arch": "73", # Snapdragon X Elite }), "CPUExecutionProvider", # fallback for non-Snapdragon ] session = ort.InferenceSession("anomaly_classifier.onnx", providers=providers) result = session.run(None, {"features": feature_vector}) # result[0] → class label: 0=NORMAL, 1=SUSPICIOUS, 2=THREAT # result[1] → confidence scores [0.0 – 1.0]

Data privacy — a technical commitment, not a marketing claim

No network egress in the AI pipeline

qai_hub_models operates in fully local mode after the initial model download. Inference makes zero outbound connections.

Payload content is never stored

Only packet flow statistics (counts, timings, sizes) are processed. Payload content is discarded at the capture layer via a strict whitelist of extracted fields.

All data stays in memory

No threat event data is written to disk by default. The user explicitly triggers export when generating a CERT-In report.

Localhost-only API

The FastAPI server binds exclusively to 127.0.0.1 — it cannot be accessed from other devices on the network.

Innovation & Use Cases

What makes this novel — and who it helps

HexaSentinel's novelty isn't a single breakthrough technique — it's a specific combination that didn't exist before: an on-device AI security analyst running on consumer hardware available today, with no meaningful accuracy or capability degradation compared to cloud alternatives.

Scenario 1 — Education

Protecting PVGCOET's network — a real deployment context

The college network at PVGCOET, Pune connects hundreds of student devices, lab computers, IoT sensors, and administrative systems across multiple buildings. An IT administrator today has no AI-powered threat detection, only basic firewall rules that block known-bad IPs but cannot detect novel attack patterns — and zero natural-language explanation of raw log alerts.

With HexaSentinel installed on the admin's HP AI PC: continuous local monitoring without any cloud subscription, real-time anomaly detection, and plain-English alerts that even a non-specialist can act on. No CERT-In expertise required to interpret the output.

Scenario 2 — BGP Attack Detection

Catching BGP hijacks at the endpoint level

When a BGP prefix hijack redirects traffic through a malicious autonomous system, the effects appear on endpoint devices: sudden latency spikes, unusual DNS failure rates, unexpected TCP retransmissions. HexaSentinel's ONNX classifier detects these secondary effects without needing access to BGP routing tables — and Llama 3.2 3B explains exactly what it found:

CRITICAL — Detected unusual DNS failure rate (47% vs 2% baseline) combined with increased TCP retransmission rate. Traffic patterns are consistent with a BGP prefix hijack or upstream routing anomaly. → Recommend verifying routing path with traceroute → Consider switching to DoH (DNS-over-HTTPS) with a trusted resolver → Contact your ISP if anomaly persists beyond 5 minutes

This is exactly the contextual, actionable security guidance SHYEN aimed to provide via cloud AI — now running entirely on the Hexagon NPU.

Conclusion

An AI security analyst in your pocket

The capabilities HexaSentinel delivers were, until now, available only through expensive enterprise cloud security subscriptions — tools that are fundamentally inaccessible to the Indian SMBs, academic institutions, and individuals who need them most.

HexaSentinel addresses this directly. By re-architecting SHYEN onto the Snapdragon X Elite platform — replacing cloud AI with Qualcomm AI Hub models running on the Hexagon NPU — HexaSentinel delivers AI-powered threat detection and natural-language explanation directly on a consumer HP AI PC, with zero internet dependency at runtime.

The project is a concrete demonstration of what becomes possible when a model like Llama 3.2 3B runs at the edge: not a compromise relative to cloud AI, but a genuine advancement in privacy, latency, resilience, and power efficiency. The device becomes its own security analyst — with no subscription, no data egress, and no single point of failure.
